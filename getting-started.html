Getting started

Three paths, depending on what you want to do: install the app, build a pack on your computer, or contribute to the code.

  • Install the app
  • Build a first pack
  • Contribute to the code

Install the app

The app is not available yet. It will come out on Google Play first, as an internal test, then for everyone. The iPhone version will follow.

To know when it comes out, follow the Google Play release issue on GitHub.

Build a first pack

Today, a pack is built on a computer with the project's command line. You then look at it in the viewer, in your browser. The maps on this site come from there.

What you need

  • A Linux computer. The project is developed and tested on Linux.
  • git and rustup. The repository pins the Rust version in rust-toolchain.toml; rustup toolchain install, run inside the repository, installs it.
  • An internet connection for the first run, and a few gigabytes of disk. The source cache takes 5 GB for the two test sites.
  • Optional: a Météo-France API key, for the day's avalanche bulletin. Without a key, the data pipeline reads the public archive of bulletins.

1. Get the code

git clone https://github.com/traceblanche/traceblanche
cd traceblanche
cargo run --release -p skimap-cli -- sites

The last command builds the command line, then lists the known sites. The command line prints in French:

cervieres          Cervières (05, INSEE 05027)
  massif Météo-France   : 17 Queyras (vérifié sur les polygones snowtools) ; BERA : oui
chapelle-des-bois  Chapelle-des-Bois (25, INSEE 25121)
  massif Météo-France   : 55 Haut-Doubs / 56 Haut-Jura (vérifié sur les polygones snowtools) ; BERA : non

2. Build the pack

cargo run --release -p skimap-cli -- build-all cervieres

The command downloads the sources, computes each layer in the order of their dependencies, then writes the pack to data/out/cervieres/pack/. It prints one line per step, with its time and key figures:

The first run downloads the sources: LiDAR HD terrain, Plan IGN tiles, an OpenStreetMap extract, the snow simulation, the ARCEP maps. With the cache already filled, the build takes a few minutes, most of them for avalanche exposure. The Cervières pack then weighs 39.6 MB, the Chapelle-des-Bois pack 35.0 MB.

Sources restricted to personal use stay disabled by default: they never go into a published pack. Their steps are then skipped.

3. Look at the pack

cargo run --release -p skimap-cli -- serve

Then open http://127.0.0.1:8765/tools/viewer/index.html?pack=../../data/out/cervieres/pack/ in your browser. The viewer's panel picks the map style (cross-country, backcountry, guidance) and the layers; tapping a feature opens its details. The viewer loads MapLibre and PMTiles from jsDelivr the first time; after that, all data comes from the pack, on your machine.

4. Compute a route

cargo run --release -p skimap-cli -- route cervieres \
  44.85894,6.725006 44.84465,6.8157 --date 2027-01-15 --start 13:00
44.85894,6.72501 → 44.84465,6.81570 (cervieres, style classique) : 11.36 km, D+ 462 m, D− 145 m
temps estimé (C5) : 2h15 (montée 1h48, plat 0h22, descente 0h05), 5.1 km/h de moyenne
C7, départ 13:00 le 2027-01-15 : coucher du soleil 17:16, fin du crépuscule civil 17:49, retour au plus tard 17:19 (crépuscule − 30 min) ; arrivée prévue 15:41 (temps × 1.2), marge 1h38

The route is written as GeoJSON to route.geojson. The other commands are described in docs/architecture/compiler.md (in French).

Contribute to the code

The repository is a Rust workspace: one crate per domain (trails, terrain, snow, zones, huts, network, avalanches, pack, core, voice) and a command line that ties them together. docs/architecture.md (in French) maps it out. The Android app, in Kotlin, will join it.

  1. Pick an issue, or open one to describe your change before you spend time on it.
  2. Write the test that proves the change. If a reference output moves, update it in the same commit and explain the difference.
  3. Run the checks: 
    cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
  4. Sign off each commit with git commit -s, under the Developer Certificate of Origin.
  5. Open the pull request. Paste the output of the commands and tick the sentence agreeing to the licence and to the app store exception.

Contributions written with an AI tool are welcome: you review them, you bring the evidence and you answer for them as for your own code.
